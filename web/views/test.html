この実装の受け渡し

Dream とテンプレートの間で値がどう流れるか。htmx より下の層の話です。

1. html が OCaml の関数になるまで

web/views/index.html <- あなたが書くのはここだけ | | app/lib/gen_views.sh | 1行目のコメントを "let ... =" に置換 | dream_eml で HTML を Buffer への追記に変換 v _build/.../app/lib/views.ml module Index = struct let render ~author = ... end | v App.Views.Index.render ~author:"..." -> string | | app/bin/main.ml の page が layout で包む v Dream.html -> レスポンス

ファイル名がモジュール名になります。web/views/entry.html を置けば App.Views.Entry が生えます。dune ファイルを触る必要はありません。

2. 署名は1行目のコメントで宣言する

これが唯一の OCaml との接点です。ここに書いた通りの引数が呼び出し側で要求されます。

<!-- render ~author -->              App.Views.Index.render ~author:"zukimo"
<!-- render ~title inner -->         App.Views.Layout.render ~title:"にっき" inner
<!-- render ~date ~body -->          App.Views.Entry.render ~date:"..." ~body:"..."
<!-- render () -->                   引数なし

省略するとビルドが止まります。行番号を元の html と合わせるために必須にしてあります。引数を渡し忘れれば OCaml の型検査で落ちます。

このページの署名は <!-- render ~author --> で、 main.ml から渡ってきた値は: <%s author %>

3. 値の埋め込みと自動エスケープ

<%s ... %> の中身は任意の OCaml 式です。変数だけでなく関数呼び出しも書けます。

<%s e %>    string を挿す。HTMLエスケープあり
<%s! e %>   string を挿す。エスケープなし（他のテンプレートの出力用）
<%i e %>    int
<%f e %>    float
<%B e %>    bool

下は同じ文字列を両方の記法で出しています。エスケープ側はタグが文字として見え、生の側はブラウザがタグとして解釈します。

<%s "<b>太字</b>" %> <%s "太字" %>
<%s! "<b>太字</b>" %> <%s! "太字" %>

記事本文やタイトルのように人が書いた値は必ず <%s %> 側を使います。 <%s! %> を使ってよいのは、別のテンプレートが返した文字列を差し込むときだけです。

4. 同じ URL が完全ページと fragment を返す live

main.ml の page が HX-Request を見て出し分けています。下のボタンは素の fetch で同じ / を2通りに叩きます。htmx が読み込まれていなくても動きます。

let page request ~title body =
  let headers = [ ("Vary", "HX-Request") ] in
  match Dream.header request "HX-Request" with
  | Some "true" -> Dream.html ~headers body
  | _ -> Dream.html ~headers (layout ~title body)

5. リクエストから値を取る

route の引数と query は Dream 側で受け取り、テンプレートには引数として渡します。テンプレートがリクエストを直接触ることはありません。

Dream.get "/t/:tag" (fun request ->
    let tag = Dream.param request "tag" in
    let page_no = Dream.query request "page" in     (* string option *)
    page request ~title:tag (App.Views.Tag.render ~tag))

Dream.header request "HX-Request"     htmx が付けるヘッダ
Dream.body request                    POST の本文（promise）
Dream.param request "tag"             route の :tag

この分離のおかげで、テンプレートは Dream にも Lwt にも依存しません。docs/diary-architecture.md §3 の「shared は Dream に依存させない」と同じ考え方です。

ヘッダ効果
